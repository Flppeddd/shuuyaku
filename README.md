# 站点聚合与线路规划工具

打开 `聚合工具.html` 即可使用。

## 代码结构

- `聚合工具.html`：页面结构和第三方脚本入口。
- `css/app.css`：页面样式。
- `js/app-state.js`：配置、运行状态及异步规划版本号。
- `js/io/csv.js`：CSV 导入解析。
- `js/services/routing-service.js`：地理距离、高德请求队列、限流和距离缓存。
- `js/domain/aggregation.js`：上车点聚合算法。
- `js/domain/route-planner.js`：线路分配、排序、平衡、约束修复和指标计算。
- `js/io/route-excel.js`：路线 Excel 导入解析。
- `js/vendor/xlsx.full.min.js`：内置 Excel 读写库，导入和导出无需访问外部 CDN。
- `js/app.js`：页面事件、地图绘制、手动编辑和导出流程。
- `全部站点.csv`：公交站数据库源文件，包含原侧与“(对侧)”站点。
- `stops_data.js`：由`全部站点.csv`生成的浏览器内置副本，用于兼容直接打开HTML。

## 加载顺序

这些文件使用普通浏览器脚本而不是 ES Modules，以继续支持直接从本地打开页面。`聚合工具.html` 中的脚本顺序不可随意调整：状态和服务需要先于领域算法及页面入口加载。

线路站序确定后，程序会逐站比较“前一站→当前站”与“前一站→对侧站”的高德驾车距离和时间。驾车距离较短的一侧优先；距离相同（1米误差内）时以时间较短者优先，并同步替换最终上车点名称与坐标。

若真实驾车路线仍存在人数、站点数、里程或漏站超限，程序会持续生成并绘制不同候选方案。只有降低超限条数、超限程度，或在约束相同的情况下明显缩短总里程的方案才会被接受；任一次改善都会清零失败计数，只有后续连续三次无法生成更符合要求的方案时，才停止并输出当前最佳路线。

## 后续开发原则

聚合和线路规划逻辑应继续保留在 `js/domain` 中，避免直接操作 DOM。高德相关请求统一放入 `js/services/routing-service.js`；页面元素及地图覆盖物的更新统一放入 `js/app.js`。
